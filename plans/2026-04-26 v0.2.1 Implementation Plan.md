## 3. Architecture Targets

Per §8 Q3 (chosen option (c)), the post-PR layout is a three-tier split:

```
src/
  main.ts
  settings.ts
  settings-paths.ts
  domain/                        # pure: no obsidian imports
    hash.ts
    types.ts                     # extracted from index.ts (Phase 7)
    epley.ts                     # extracted from index.ts (Phase 8)
    workout-note-model.ts
    workout-note-serializer.ts
    journal-grammar.ts
    exercise-registry.ts
    import-mapping.ts
  vault/                         # obsidian-aware, non-UI
    file-session.ts
    exercise-registry-vault.ts
    vault-utils.ts
    index.ts                     # vault scanner
    dashboard.ts
  ui/                            # views and modals
    workout-editor-view.ts
    import-modal.ts
    create-missing-exercises-modal.ts
    parse-diagnostics-modal.ts
```

Tier rules:

- `src/domain/**` must not import from `obsidian` (grep-verifiable).
- `src/vault/**` may import from `obsidian` and from `src/domain/`. It must not import from `src/ui/`.
- `src/ui/**` may import from anywhere.
- Top-level `main.ts`, `settings.ts`, `settings-paths.ts` stay flat because they are the plugin entry-point and configuration glue, not domain/vault/ui code.

Within a tier, imports use `./` relative paths. Cross-tier, use `../<tier>/` paths (e.g. `../domain/types`).
